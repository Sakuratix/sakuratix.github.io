infra-lab

          
# platform / reference repositoryплатформа / эталонный репозиторий

          
One small service taken all the way to production in a single repository: container, pipeline, Kubernetes chart, cloud infrastructure, server baseline and monitoring.

          
Один небольшой сервис, доведённый до прода в одном репозитории: контейнер, пайплайн, Helm-чарт, облачная инфраструктура, базовая настройка серверов и мониторинг.

          
    
            
  • Tests run inside the Docker build, so an image that fails them never exists. Trivy then blocks the push on HIGH and CRITICAL findings: it caught two in the Debian base image, fixed by patching the layer.
    • 
            
  • Zero-downtime rollouts: on SIGTERM readiness drops first, preStop gives the ingress time to notice, PDB and HPA keep capacity.
    • 
          

          
    
            
  • Тесты запускаются внутри сборки Docker: образ, который их не прошёл, просто не появится. Дальше Trivy блокирует публикацию при HIGH и CRITICAL. Он нашёл две уязвимости в базовом образе Debian, исправлено обновлением пакетов.
    • 
            
  • Обновления без простоя: на SIGTERM сервис сначала перестаёт быть ready, preStop даёт ingress время это заметить, PDB и HPA держат запас.
    •

k3s-gitops

          
# kubernetes / gitopskubernetes / gitops

          
A single-node k3s cluster where everything after Argo CD comes from git. Changes go through a commit; anything edited by hand in the cluster is reverted.

          
Однонодовый k3s, где всё после Argo CD создаётся из git. Изменения идут только через коммит, ручные правки в кластере откатываются.

          
    
            
  • App of apps with sync waves: the ingress controller and cert-manager come up first, then the issuer and monitoring, then the workloads.
    • 
            
  • Chart versions and values live apart (multi-source Applications), so upgrading a chart and changing its settings are separate, reviewable commits.
    • 
          

          
    
            
  • App of apps с sync-wave: сначала ingress-контроллер и cert-manager, потом issuer и мониторинг, потом приложения.
    •

alertmanager-telegram-relay

          
# observability / alertingмониторинг / алертинг

          
A small dependency-free service that turns Alertmanager webhooks into readable Telegram messages: grouped, marked by severity, HTML-escaped and kept under Telegram's length limit.

          
Небольшой сервис без зависимостей: превращает webhook от Alertmanager в понятные сообщения в Telegram. Группирует алерты, помечает по severity, экранирует HTML и укладывается в лимит длины.

          
    
            
  • If Telegram is down, the relay answers 502 and Alertmanager retries on its own, so an alert is delayed rather than lost.
    • 
            
  • The message format lives in code and is covered by tests, not in Go templates buried in the Alertmanager config.
    • 
          

          
    
            
  • Если Telegram недоступен, сервис отвечает 502, и Alertmanager повторяет отправку сам: алерт задержится, но не потеряется.
    • 
            
  • Формат сообщений лежит в коде и покрыт тестами, а не спрятан в Go-шаблонах внутри конфига Alertmanager.
    •

pg-backup-s3

          
# databases / backupsбазы данных / бэкапы

          
PostgreSQL backups to S3-compatible storage in one Bash script: dump, compress, verify, upload, prune old copies and report to Prometheus.

          
Бэкапы PostgreSQL в S3-совместимое хранилище одним Bash-скриптом: дамп, сжатие, проверка архива, загрузка, удаление старых копий и метрики для Prometheus.

          
    
            
  • If the server was off at night, the systemd timer runs the missed backup on boot (Persistent=true).
    • 
            
  • Two alerts: the last backup failed, or there has been none for 26 hours. A backup that failed silently is worse than no backup.
    • 
          

          
    
            
  • Если сервер ночью был выключен, systemd-таймер снимет пропущенный бэкап после включения (Persistent=true).
    • 
            
  • Два алерта: последний бэкап упал или его не было 26 часов. Бэкап, который тихо упал, хуже, чем его отсутствие.
    •

mikrotik-config-backup

          
# networks / config historyсети / история конфигов

          
Nightly MikroTik config export into git: one file per router, a commit only when something changed, secrets excluded.

          
Ночной экспорт конфигов MikroTik в git: файл на каждый роутер, коммит только при изменениях, секреты не попадают.

          
    
            
  • RouterOS writes a timestamp into the first line of every export. The script strips it, so only real changes become commits.
    • 
            
  • Exits non-zero if any router does not answer, so cron or systemd notices instead of skipping it silently.
    • 
          

          
    
            
  • RouterOS пишет дату в первую строку каждого экспорта. Скрипт её вырезает, поэтому коммитятся только настоящие изменения.
    • 
            
  • Завершается с ошибкой, если какой-то роутер не ответил: cron или systemd это заметят, а не пропустят молча.
    •
